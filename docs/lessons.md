# Lessons（可复用教训；同一教训第二次出现必须升级为结构/ADR）

- **文献里的 "zero-shot" ≠ 跨输入迁移**：self-play 驾驶论文的 zero-shot 指固定模型观测契约 + per-benchmark 环境适配器，且基准交通是 IDM/回放/规则，从不是多样化学习对手（GigaFlow App.E 核实）。读论文时先问"适配器在哪"。
- **self-play 不是闭环分数的效率来源**：CaRL 1B 样本 → nuPlan Val14-R 93.12，GigaFlow 1T 样本 → 93.8（1000× 换 0.7 分）；DriveZero A.5.2 篇内对照打平。它的价值要用"对手分布可控生成 + 全场安全测试"计价。
- **闭环安全分可能度量的是仿真器宽松度**：无约束动作网格让策略用违反舒适包络的机动刷安全分（jerk 越限至 4513%，Comfort-by-Construction）。报安全分必须同时审计实际运动学。
- **PufferDrive 能力断言必须按分支核实**：3.0 的噪声在 `origin/8-9_bernhard_dev`（`dev/zoo_v3.0` 无 pose-noise）；`mining_viz.py` 已被 #533 的种子化失败回放删除。引用能力前先 `git branch --contains` + 查当前树。
- **引用外部部署契约必须带代际锚点**：“17 张量”曾无标记地散在本仓 5 处文档，上游 2026-10-30 切换代际后全线漂移（nova 侧 `onnx_export.md` 同样只能靠事后注记）。已升级为结构：ADR-0006 承载代际事实 + `CONTEXT.md` 新增“Nova 部署契约 / 参考线槽位 / ego-centric RFU”术语条 + STATE 记录 nova 一手锚点文件；引用契约一律写“代际 + 日期 + 权威文件”。
- **宣布"数据缺失"前先找索引文件**：我把 `base_map.catelog`（84/115 MB）+ 6,249/10,874 个 500 m tile 的大图判成"没有地图"，据此写出一条错误的"数据供给缺口"结论。大图从来不以整图 bin 交付，`sim_map.bin` 0 字节、`routing_map.bin` 只是路由图，都不能当日志里的"没有"。缺文件时先 `ls` 目录结构 + 找 `*.catelog`/`*.catalog`/分片目录，再谈缺口。
- **指标失败先问"这段该不该被度量"**：车道贴合度 p90 33.7° 的真相是该 bag 大半时间在场站里挪车（1.5–2.1 m/s，无车道线），不是匹配错。放阈值之前先按工况切分（行驶中 ≥2 m/s vs 场站），把"数据覆盖不足"与"算法错误"分开计。**放宽阈值永远是最后手段。**
- **"编译器太旧"先别升级系统**：`pufferlib._C` 编不过的真因是 torch 强制 `-std=c++20`（g++ 9.4 只认 `-std=c++2a` 且缺 `<compare>`）。把 gcc 13 装在 conda 的 build-only 环境里、用 `CC`/`CXX`/`PATH` 只影响当前 shell，就解决了，没有任何系统级改动。顺带发现两个隐藏坑：① 本机 CUDA toolkit 12.6 vs torch 13.2，CUDA 内核根本编不了（要 `PUFFER_BUILD_CPU_ONLY`）；② `torch.compile` 训练时会**再调一次编译器**，所以运行前也要 `source` 工具链，光编一次 `_C` 不够。
- **GPU 不可用先看 CUDA 代际，不要先动驱动**：driver 535（CUDA 12.2）跑 `torch 2.15.0+cu132` 直接判 false。换成 `2.14.1+cu126`（与本机 toolkit 12.6 同代）后 `is_available()` 为 True —— CUDA 12.x 的 minor version compatibility 允许 12.6 运行时跑在 12.2 驱动上。代价只是 torch 退一个小版本，比升级驱动安全得多。装 cu126 wheel 时 `pypi.nvidia.com` 在国内会超时，加清华源做 `--extra-index-url` 并设 `--index-strategy unsafe-best-match` 才能把 nvidia-* 依赖拉全。
- **主键碰撞会让统计灌水 9.5 倍**：`scenario_id = bag#int(t_start/0.1)` 在 86 Hz 的 pose 流上把约 9 帧压成同一个 id，于是 779 条"切片"只有 82 个不同场景、场景 bin 互相覆盖，M7-2/M7-3 的场景数全被放大。派生 id 必须由**原始时间戳精度**（毫秒）+ 模板 + 去重共同保证唯一，并在生成端断言 `len(unique) == len(rows)`。
- **环境拒绝加载时先看它要什么可选段**：场景 bin 缺 `SPDZONE1` 段时，只要 `speed_limit_random_prob > 0` 引擎就整份 map 拒载（"carries no speed zones"）。自己写二进制格式时，可选尾段的**存在条件**要和读取方的默认配置对齐，否则训练一开就崩。
- **场景包络是判据的一部分**：`lane_departure` 判"离最近车道 > 0.9 m"，而地图里只写了 route ±20 m 的车道时，策略一开快就开出车道集、`lane_dist` 撞上 4.0 归一化上限，被记成"越道"。把包络扩到 ±40 m 后，同一批 71 个场景里策略侧违规从 71 降到 1 —— 改包络等于改判据，必须和数字一起记录，否则"71 个 bad case"在两次实验里指的不是同一个东西。
- **"参考零点 0 违规"往往是测量错了**：replay 模式贴 log 位姿、不积分动力学，`sim_speed`/`accel`/`jerk` 全为 0，于是带速度门限的谓词在参考跑里永不成立，量出"场景里没有违规"的假结论。凡是用 replay 做参照，速度必须由相邻位姿反推。
- **`total_timesteps` 不是"经验量"**：PufferDrive 数的是**所有 agent 的步**。场景里 25 辆车但只控 1 辆时，2M agent-steps 只等于 80k 被控步 —— 预算看起来很大，实际训练量被稀释 25 倍。改场景规模时必须把预算换算成"被控步数"，否则两次实验不可比。
- **加场景 ≠ 变好，先看奖励有没有对应的信号**：把 174 个补对手的 cut_in/ttc 场景塞进训练集，违规数一动不动（39→39），因为奖励里没有"与对手的交互后果"。评测集可以靠补数据扩大，训练集不行 —— 训练集要靠**奖励覆盖**扩大。
- **惩罚不等于学会**：给"离障碍物近"加逐帧常数惩罚，在有 24 辆回放对手的场景里等于持续扣分，策略被推向反常行为（自车类违规从 70 升到 143）。要让 agent 学会礼让，奖励必须落在**事件**上（场景结束按约束谓词给一次 ±奖励），而不是落在每一帧的几何量上。
- **选奖励指标前先看它的取值分布**：本仓 `ttc` 实测只取 0 和 5.0（300 步里 20% 为 0，中间值 0 个），是二分信号，做不出渐变惩罚；`distance_to_collision` 是 1.6–2.2 m 的连续量，才适合做 shaping。指标"存在"不等于"可用"。
- **评测 harness 手搓的每一环都是契约，"跑得通"≠"等价"**：同一权重训练里在开、harness 里 0.00 m/s，逐位对拍后发现 **obs 完全一致**——真正的偏离是 argmax 选动作（训练 eval 是 mean：物理表概率加权期望）+ dt 覆盖（0.1 vs 训练 0.3，速度低估 ~8×）。驻车分布众数=no-op（~63%）时 argmax 自锁。教训已升级为结构：`select_eval_action` 单一出口 + `test_policy_eval_action_contract.py` 三测钉住（ADR-0010）。离线评测凡手搓 logits→动作、覆盖 env 参数，都必须先对拍训练路径。
- **`puffer train` 启动即覆写 `data_dir/config.yaml` 快照**：训练进程把"基础配置 + 本次 override"写进 `train.data_dir`（默认 `experiments/`）——多轮实验共用默认 data_dir 时，上一轮的配置快照会被静默覆盖（roundC 快照就是这样丢的，靠会话记录重建）。多轮训练必须给每次 run 独立 `train.data_dir`；`experiments/config.yaml` 被 harness（`training_env_config()`）当训练契约读取，它若被覆写成另一轮的配置，评测契约就悄悄漂移。重建件：`.scratch/config_roundC_reconstructed.yaml`。
- **Hydra override 要与 base schema 对齐**：快照里由 `normalize_puffer_drive_config` 派生的键（`env.eval_mode`、`train.use_rnn`、`train.profile`…）不在 base yaml 里，直接 `key=value` 会报 "Could not override"；要么加 `+` 前缀，要么确认派生默认值就是想要的、直接省略。从快照生成 override 时先 diff base schema，别盲目全量透传。
- **一次性事件罚金必须压过整个回合的 shaping 奖励流，否则会被摊销掉**：-5 的越道一次性惩罚 vs 每步速度奖励，agent 学出"踩满油门画圈刷速度 → ~20 步冲出路网 → 吃罚金死亡重置"的局部最优（单集总转向 36 rad，训练 offroad_rate 恒 1.0）。诊断签名：episode_length 短 + offroad_rate 不降 + 轨迹总转角巨大 + 纵向动作只取加速档。修法方向：罚金量级对齐回合奖励总和，或直接关小与之竞争的逐步奖励；别急着加更多 shaping 项。
- **"配置里的奖励系数"在 randomize 打开时是摆设**：`reward_randomization: true` 时 `generate_reward_coefs()` 用 `REWARD_BOUNDS` 抽样覆盖 `lane_center/lane_align/offroad/comfort/...`，`reward_velocity` 更是硬编码 `2.5e-3`。于是"把 reward_velocity 从 0.0025 调到 0.0005"这类调参**完全不会生效**，而训练日志照样有输出。调参前先确认旋钮是活的（`scripts/reward_scale_report.py` 的 `live_coefs` 门）。
- **先算量级再谈归因**：把"velocity farming"当作 event_reward_v1 画圈的原因，算一下就不成立——`velocity_progress = max(cos,0)` 且只在 >2.5 m/s 时非零，一集（60 步·dt 0.3）上限只有 `2.5e-3×0.3×60 = 0.045`，攒不出一次 -5.0 的罚金。真实结构是**密集项 1e-3、事件项 O(1) 且在 154/154 个场景都触发（常数）**，优势函数里根本没有信号。奖励归因必须先把每项的一集累积量列出来。
- **一张表，两个教训**：①一次性惩罚 > 4×密集累积就是"付一次钱之后越道免费"；②正向累积 < 0.25×可避免的负向累积就是"趴着不动在构成本上最优"。v2a（0.043）和 v3（0.022）都落在第②条上，训练后分别是"开快冲出去"和"1.15 m/s 爬行"。这两条现在是开训前置门（`lane_signal / event_dominance / positive_channel`），红的不开训。
- **dt 是动作空间的一部分**：横向动作是 3 档 jerk {-4,0,+4}，`a_lat += j_lat·dt`。dt=0.3 时一步就是 ±1.2 m/s²、5 m/s 下约 13.7°/步，而握车道需要的修正量级是 0.01 rad/s —— 横向控制在 dt=0.3 上是 bang-bang 的。对照实验：同一 IDM、同一场景，dt 0.3 → max|lane_dist| 4.0（撞上限、28 步后 offroad），dt 0.1 → 1.14–1.20（52 步不越道）。跑 900k 步学不会的东西，可能根本不是奖励问题。
- **"活得更久"要看物理时长，不是步数**：dt 0.3 → episode 16/60 步，dt 0.1 → 43–56/60 步，看起来好了 3 倍，物理上都是 4.4–4.8 s。跨 dt 比较训练指标必须换算成秒。
- **奖励系数的"值"也是观测上下文**：`context_dim = num_reward_coefs + goal_dim`，所以同一份权重换一份配置快照评测，中位车速 1.85 → 4.56 m/s、撞 lane_dist 上限的场景 19 → 131。多轮实验评测必须 `--run-config <data_dir>/config.yaml`，别让 harness 去读别轮的快照。
- **离线排查要有对照控制器**：policy 学不会横向控制时，先用同一 env 跑 IDM（`sdc_controller=idm`）。IDM 也开不住 = 环境/动作契约问题；IDM 开得住 = 策略/奖励问题。本次就是靠这个对照把 80% 的排查范围一刀切掉的。
- **横向动作的档位密度就是控制精度**：`a_lat` 是积分量（`a_lat += j_lat·dt`），3 档 jerk {-4,0,+4} 在 dt 0.1 下每步只能把横向加速度改 0.4 m/s²，而车道保持要的修正量级是 0.05 m/s²。结果策略只能"不打方向"或"猛打"。改成 7 档 {-4,-1.5,-0.5,0,0.5,1.5,4} 后，**同预算 900k 步违规 153/154 → 107/154、中位 lane_dist 峰值 1.445 → 0.967 m**。调奖励之前先确认动作空间能表达目标行为。
- **"改动作表"是破坏性变更**：类别数 12 → 28，所有旧 checkpoint 直接 `size mismatch` 加载失败。改档位必须当新实验开一轮，并把依赖旧权重的测试改成脚本策略或显式 skip（`grep '12 → 28'`）。
- **绝对门限与"噪声带"撞车时要拆成两件事**：`|lane_dist| > 0.9 m` 同时被用作「挑 bad case」和「评测策略」。前者需要**去偏**（参考司机本来就偏 0.80 m，50/154 的"越道"只有 0.2–0.3 m），后者必须**绝对**（去偏会把把车摆正的策略判成偏离 0.8 m）。实测证据：v6 在绝对口径下中位峰值 0.967、在去偏口径下反而"违规" 140/154。
- **对照实验要能一刀切掉范围**：怀疑策略学不会时，先用同一 env 跑别的控制器（IDM/脚本策略）。IDM 也开不住 → 环境/动作契约问题；IDM 开得住 → 策略/奖励问题。本轮两次靠它定位（dt=0.3 的横向不可控、事件奖励的触发条件）。
- **训练曲线不判别好坏，最好的权重在中途**：v6（900k，LR 衰减快）评测 107/154、中位 `lane_dist` 峰值 0.967 m；同一配置拉到 2.7M（LR 衰减慢 3×）变成 139/154、1.771 m —— 而两者训练末都写 `offroad_rate 1.000`。`total_timesteps` 不只是一条"多训就好"的旋钮，它同时改 LR schedule。**必须按部署 KPI 周期性选点**，别用训练日志的聚合指标选模型。
- **正向通道的可用性要先量，再改**：`num_goals_reached` 一直为 0，审计发现 goal 没放错（正前方 31.6 m、离车道中心 0.01–0.42 m、航向偏 3°），而是 **60 步 × dt 0.1 = 6 s 的窗口刚好覆盖 30 m**。把 `max_goal_spacing` 200→40 让 goal 进窗口后 `num_goals_reached` 到 0.091，但违规反而从 107 涨到 149 —— "让奖励能拿到"不等于"让行为变好"，两者都要量。
- **KPI 的分母必须是一个文件，不是脚本里的常量**：`lane_departure` 的 154 个切片里，50 个的真实偏移只有 0.2–0.3 m（基准线坐在 0.9 m 门限附近）、34 个边缘、70 个真越道；另有 32 个场景车道关联中途变号。分母散落在三个脚本里时，"修复率"会随口径漂移；现在是 `spec/badcase_set_v1.yaml`（`scripts/scene_badcase_set.py` 生成，`regression_retention.py --badcase-set` 消费，`tests/unit_tests/test_badcase_set_contract.py` 钉住）。同一个 v6 权重：154 全集读 107/154，新分母读 **36/70** —— 差一倍多，全部来自假 case 与翻转窗口。
- **选点要在训练时就留好权重**：`checkpoint_interval` 默认 50 epoch 且**逐个删除旧权重**，所以"事后挑最好的点"在默认配置下不可能（`models/` 里只有一个文件）。要按 KPI 选点就同时设 `train.checkpoint_interval`（大一点）+ `train.keep_checkpoints=true`，再用 `scripts/kpi_select.py`。
- **按子集 KPI 选点会选出"分母上完美、分母外乱开"的权重**：v8 选中的 checkpoint 在 genuine 70 个场景上 0 违规、中位车速 2.13 m/s，但同一份权重在 artefact 桶（50 个"参考司机没越道"的简单场景）里以 **5.4 m/s** 开出去、`lane_dist` 撞归一化上限。分母只应该决定**修复率**，健康指标（全集 clamp 比例、全集车速）必须同时进选点排序，否则选点本身变成一个过拟合通道。
- **同一轮的 checkpoint 之间差异可以比"实验臂"之间还大**：v8 的 9 个 checkpoint 违规数是 0 / 52 / 59 来回跳（epoch 200、600 是 0，其余 59），而训练日志这段期间几乎不变化。凡"某个配置比另一个好/坏"的结论，先确认不是选到了不同的 epoch。
- **高速会吃掉横向精度，而奖励里没有这一项**：v8-best 在 genuine 桶（路径曲率中位 0.038 /m，弯道）中位车速 2.13 m/s、峰值 0.70 m；同一份权重在 artefact 桶（曲率 0.004 /m，直道）开到 5.38 m/s（GIF 里瞬间 9.4 m/s）、峰值撞上限 4.0。策略"直道就加速"本身不算错，但车道保持的容错随速度下降，而 `reward_lane_center` 是**与速度无关**的常数罚 —— 于是快的时候越道几乎不额外付费。修法方向：让横向代价随速度加权（`× (1 + v/v_ref)`）或给速度加上限，而不是继续加罚系数。
- **健康指标要进选点排序，但只能当 tie-break / 硬门**：把 `clamp_scenes` 放在违规数之前，会让"违规 59 但 clamp 少"压倒"违规 0"，荒谬；放在之后又是纯 tie-break。做法：字典序 `(不动车, 违规数, 全集 clamp, 中位峰值, -车速)` + `--require-health` 硬门，并始终打印警告。
