一句话：我们的场景 bin 里原来只有自车一辆车。像"与前车 TTC 过短""被加塞"这类违规， 本质是两辆车之间的关系，没有第二辆车就不可能判出来。补对手 = 把 bag 里感知到的 其它交通参与者写成 agent 补进场景，让这些谓词有机会非平凡。

脚本：scripts/partner_scenes.py + scripts/scene_from_slice.py 的 load_obstacle_tracks / partner_agents。验收物：docs/html/partner_scenes_v0.html。

2. "对手"从哪里来：不是仿真出来的，是感知看到的

这一点最容易误解。对手轨迹不是我们编的、也不是引擎生成的，而是直接取自 bag 里的 /apollo/perception/obstacles 通道 —— 也就是当时自车的感知系统看到的东西。

这意味着三件事：

  1. 它带着真实感知缺陷：遮挡导致的轨迹断点、跟踪 id 切换、速度抖动都在里面；
  2. 它不是真值：与"真值里那辆车"可能有几百毫秒的延迟和几十厘米的偏差；
  3. 它天生与自车同步：同一条 bag、同一个时钟，不需要时间对齐。

对训练来说这恰好是我们想要的 —— 训练契约要匹配的是部署时的感知质量，不是真值。

3. 怎么变成一个 agent：四道筛选

# scripts/scene_from_slice.py
load_obstacle_tracks(bag)      # ① 按 track id 归并成轨迹
partner_agents(tracks, window, origin_x, origin_y)   # ②③④ 筛选 + 转 agent
步骤 规则 为什么
① 归并 按 obstacle.id 聚合，时间戳排序 感知每帧给一坨障碍物，要先拼成"同一个物体的时间序列"
② 出现率 窗口内可见 ≥ 60% 的帧 一闪而过的检测（鬼影）不该变成一辆车
③ 距离 距自车轨迹最近 ≤ 80 m 80 m 外的车对 ttc/加塞没有因果作用，只会稀释观测
④ 数量 最多 24 辆，按距离从近到远 引擎的 partner 槽位与观测带宽有限；先保近处的

然后每辆车写成 PufferDrive agent 的字段：

字段 来源
x, y 障碍物位置 − 场景原点（必须先平移，float32 在 3.4e6 m 量级只有 0.25 m 分辨率）
h（航向） 障碍物 theta
vx, vy 障碍物速度
len, wid, hgt 障碍物尺寸中位数；缺失时用 4.6 × 1.9 × 1.6 m
valid 该帧是否可见（不可见 = 0，引擎会跳过）
type Apollo 类型 5→VEHICLE、4→CYCLIST、3→PEDESTRIAN
mark_as_expert 1 —— 关键：这辆车按 log 回放，不受策略控制

自车则是 mark_as_expert = 0，由策略（或 IDM/replay 裁判）控制。

4. 为什么"回放"而不是"会反应"

当前对手是脚本化的：照着自己那条真实轨迹走，你怎么开它都不变。

能力 现在（回放对手） 需要什么才能做到
让 ttc / 加塞 / 碰撞谓词非平凡 ✅ —
复现"真实世界里发生过的那次加塞" ✅ —
测"策略礼让后对方会不会感激/抢行" ❌ 交互式对手（IDM / 学习型策略）
对抗性搜索（找策略的软肋） ❌ self-play 对手分布（ADR-0003 Σ）

所以这一步的定位很明确：让判据能工作，而不是做交互仿真。真正的交互对抗是 M8 的事。

5.1 顺带抓到的口径 bug（值得单独记）

3123 一开始是 0/39。查下来不是缺对手，而是 guard 阈值：

# cut_in_conflict 的 guard
guard: {metric: lane_dist, op: abs_gt, threshold_param: adjacent_lane_m}
# 原值 1.0 m

引擎在 3123 上量到的 |lane_dist| 峰值是 0.97 m —— 差 0.03 m，guard 永远不成立。

根因：bag 侧用"匹配车道的横向偏移"算加塞，引擎用"到最近车道的距离"； 两者存在系统性偏差（2714 上是 −0.31 m）。把 guard 改成 0.9 m（与 lane_departure 同源）后 立刻 39/39。

教训：跨实现比对同一个量时，阈值必须留出系统偏差的余量，否则 0.03 m 就能让一整批场景"消失"。

7. 常见误解

误解 事实
"对手是仿真的 NPC" 不是，是 bag 里感知到的真实车辆，按 log 回放
"补了对手就能做 self-play 了" 不能，回放对手不反应；self-play 需要 M8 的对手分布
"对手越多越好" 不是，>24 辆会挤爆观测带宽；筛选按距离从近到远
"对手位置是精确的" 不是，它带感知噪声与延迟，这正是训练要匹配的部署条件
"ttc 的默认值 5.0 说明没危险" 是哨兵值，表示"视野内没有会撞的车"；峰值 5.0 不代表触发，要看谓词是否成立
