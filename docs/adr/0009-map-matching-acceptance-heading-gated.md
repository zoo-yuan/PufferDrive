# 地图匹配的接受判据：航向门限 + 横向上限，置信率是数据质量而非正确性

Status: accepted 2026-11-05（owner 指出分块地图被我误判为缺地图；证据 `docs/measured/map_match_v0.json` + `scripts/map_match_report.py`）

## Context

bag 自车姿态要贴到 Apollo HD map 的车道中心线上，才能评 `lane_departure` / `multi_lane_wander` / `overspeed` 这 4 条约束。
最初实现是"半径内最近点"，两个实测事实把它证伪：

- **双向道路的对向车道中心线只差一个车道宽（~3.5 m）**。最近点匹配会把车贴到对向车道上，实测航向差 p90 达 **179°**（rx-3139）、121°（rx-2292）。
- **大图是分块的**：`6501_*` / `7235_*` 没有整图 `base_map.bin`，只有 `base_map.catelog`（84/115 MB）+ 6,249/10,874 个 500 m tile（`sim_map.bin` 是 0 字节，`routing_map.bin` 是路由图、无几何）。我曾据此写下"3 条 bag 无地图 → 数据供给缺口"，是**错的**。

另有第三条事实：2292 是场站作业包，大半时间以 1.5–2.1 m/s 挪车，那里本来没有车道线 —— 任何"贴合度"指标在无车道区域的失败都不是匹配的错。

## Decision

1. **加载按地图形态分派**：有 `base_map.bin` 读整图；否则读 `base_map.catelog`，按 bag 轨迹 bbox（+100 m）只解析覆盖到的 tile。**"没有整图 bin"不等于"没有地图"**。
2. **候选点必须航向一致**：`|heading_diff| ≤ 60°`，否则换下一个候选。
3. **横向超过 3 m 直接拒绝**（返回 `None`）：宁可"不出判定"，也不伪造。错配一帧就会变成一条假的车道偏离违规，比漏检更有害。
4. **置信匹配率 = (`|heading| ≤ 10°` ∧ `|lateral| ≤ 3 m`) 的帧占比，是数据质量指标，不是正确性指标**。低于 85% 标 `partial coverage` 并在报告里显式写出，**不阻断流水线**（该 bag 只是可用帧更少）。门槛只要求"有地图的 bag 里 ≥80% 置信"。
5. **报告把"行驶中"（≥2 m/s）与"场站挪车"分开统计**：混在一起时 p90 只能反映场站段，会把 85% 良好贴合误报成失败。

## Consequences

- 6/6 条 bag 匹配率 100%；lateral 中位 +0.42 / +0.01 / −0.31 / +0.12 / −0.59 / +0.01 m（系统性偏差显式保留，不静默校正）。
- 置信率 5 条 100% / 2292 72% → 车道类约束对 2292 只有约七成帧可评。这个"缺口"被写进报告，而不是被阈值吃掉。
- 挖掘切片 636 → 779（`lane_departure` 156 / `multi_lane_wander` 27 首次真实触发）。
- 匹配层不接受"平滑/插值补帧"：无匹配就无判定，provenance 里保留 `lane_id` 与 `heading_diff` 供复核。
